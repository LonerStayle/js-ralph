# vision-intake

> 비전은 **마감이 아니라 방향(북극성)** 이다. 프로젝트는 끝나지 않고 넓어지며, "완료" 는 기획(feature) 단위에만 있다.
> 그래서 이 인터뷰는 날짜 · 규모 · 최종 산출물을 묻지 않는다. 대표님이 정하는 것은 **방향 · 금지선 · 품질 기준** 까지다.
> 비전은 별도 파일이 아니라 **하네스의 CLAUDE.md 안에 직접** 합성한다 (Claude Code 자동 로드 활용).

---

## 트리거 조건

Claude Code 가 매 세션 `CLAUDE.md` 를 자동 로드하고, SessionStart hook 이 미완료 인터뷰를 알린다. `## 🔒 비전 인터뷰 상태` 의 `onboarded` 값:

- `onboarded: false` 또는 부재 → 이 skill 로 인터뷰 시작
- `onboarded: true` → 호출하지 않음

---

## 1단계 — 인사

```
대표님 안녕하십니까.
시작하기 전에 9가지를 여쭙겠습니다. 마감이나 최종 결과물이 아니라,
이 프로젝트가 향할 방향과 절대 지켜야 할 선, 모든 기능이 지켜야 할 품질 기준을 정하는 질문입니다.
답변을 CLAUDE.md 에 정리해 드리고, "확정" 해 주시면 동결한 뒤 첫 기능 후보를 제안드리겠습니다.
```

> 기존 프로젝트에 `--overlay` 로 설치했다면 `CLAUDE.md.pre-harness` 가 있을 수 있다. 있으면 먼저 읽고,
> 거기 적힌 사실(스택 · 컨벤션 · 명령)로 답을 미리 채워 질문을 줄인다.

---

## 2단계 — 9 질문

한 번에 1~2개씩 자연스럽게 묻는다.

| # | 질문 | 기대 형식 | 들어갈 자리 |
|---|------|-----------|-------------|
| 1 | **비전**: 이 프로젝트가 향하는 방향은? (끝나는 목표가 아니라 계속 가까워질 방향) | 1~2 문장 | `### 1. 비전 (방향)` |
| 2 | **사용자**: 누가, 어떤 상황에서 씁니까? | 구체적 인물 1~2명 | `### 2. 사용자` |
| 3 | **전문가**: 이 분야를 가장 잘 아는 사람은 누구입니까? (예: 세무사, 물류 운영자, 교사) | 직업/역할 + 무엇을 보는 사람인지 | `### 3. 전문가` |
| 4 | **방향 신호**: 어떤 상태면 "잘 가고 있다" 고 느끼십니까? | 관찰 가능한 신호 2~4개 (수치 가능하지만 필수 아님) | `### 4. 방향 신호` |
| 5 | **금지선**: 어떤 경우에도 하지 말아야 할 것은? | 명시적 목록 | `### 5. 금지선` |
| 6 | **품질 기준**: 모든 기능이 예외 없이 지켜야 할 것은? | 목록 — 3단계에서 분류 | `### 6. 품질 기준` |
| 7 | **외부 의존**: 필요한 API · 데이터 · 계정은? | 목록 ("없음" 가능) | `### 7. 외부 의존` |
| 8 | **기술 스택**: 기본값(Python+uv+FastAPI / React / Android-Kotlin / Postgres)과 다르게 갈 것이 있습니까? | "기본값" 또는 override | `### 8. 기술 스택` |
| 9 | **지금의 초점** (선택): 당분간 집중할 영역이 있습니까? | 한두 줄 또는 "없음" | `.harness/FOCUS.md` |

마감 · 일정 · 규모를 말씀하시면 받아 적되 비전이 아니라 **초점(9번)** 이나 **방향 신호(4번)** 로 옮겨 적고 그렇게 했다고 말씀드린다.

### 모호한 응답

항목당 보강 질문은 최대 2 round. 그래도 불명확하면 해당 자리에 `⚠️ 확정 필요: <메모>` 로 두고 진행한다.
단 **3번 전문가** 는 비워 둘 수 없다 (전문가 시야 제안이 작동하지 않는다). 대표님이 모르시면 비전과 사용자에서 가장 가까운 직업을 제안해 확인받는다.

---

## 3단계 — 품질 기준 분류 (6번)

받은 품질 기준을 하나씩 두 종류로 나눠 **표로 보여드리고 확인받는다**:

| 분류 | 뜻 | 어떻게 강제되나 |
|------|----|-----------------|
| `[측정]` | 기계로 잴 수 있음 — 커버리지, 응답 시간, 린트 경고 수, 번들 크기 등 | `.harness/verify.d/q-<번호>-*.sh` 스크립트가 미달이면 커밋 자체를 막는다. 스크립트는 첫 기획의 계획에 자동으로 포함된다 |
| `[판단]` | 사람 눈이 필요함 — 에러 메시지 친절함, 권한 체크 누락 없음, 로그에 개인정보 없음 등 | reviewer 가 **모든 노드** 에서 점검한다. 위반은 고칠 때까지 노드가 완료되지 않는다 |

- 모호한 기준은 측정 가능하게 다듬는 안을 제안한다 ("빠르게" → "주요 API p95 300ms 이하 [측정]").
- 잴 수 있을 것 같지만 스택이 아직 없어 도구가 불확실하면 `[측정]` 으로 두되, 무엇으로 잴지 한 줄 덧붙인다.
- 각 항목에 `Q-1`, `Q-2` … 번호를 붙인다.

---

## 4단계 — CLAUDE.md 합성

Edit 도구로 `CLAUDE.md` 의 `## 비전 / 사양` 아래 `### 1.` ~ `### 8.` 자리의 `*(미입력…)*` 을 답변으로 바꾼다.
6번은 정확히 이 형식으로 쓴다 (스크립트가 파싱한다):

```markdown
### 6. 품질 기준 (모든 기능이 항상 지킴)
- Q-1 [측정] 백엔드 테스트 커버리지 80% 이상 — pytest-cov 로 측정
- Q-2 [판단] 사용자에게 보이는 모든 에러는 원인과 다음 행동을 알려준다
```

9번(초점)은 `.harness/FOCUS.md` 의 `(비어 있음)` 을 답으로 바꾼다 (없으면 그대로).

**손대지 않을 영역**: `## 🔒 비전 인터뷰 상태` (5단계에서만), `## 공통 — …` 섹션 전체.

작성 후 안내:

```
대표님, CLAUDE.md 에 방향 · 금지선 · 품질 기준을 정리해 두었습니다.
품질 기준은 측정 N개(검증 스크립트로 강제) / 판단 M개(모든 리뷰에서 점검)로 나눴습니다.
수정하실 부분을 말씀해 주시고, 괜찮으시면 "확정" 이라고 해 주십시오.
```

---

## 5단계 — 동결

대표님 메시지에 `확정`, `OK`, `ok`, `진행해`, `동결`, `frozen` 중 하나가 있으면 동결한다.

> ⚠️ `onboarded: true` 로 바뀌는 순간부터 CLAUDE.md 는 에이전트가 수정할 수 없다 (PreToolUse hook 이 차단).
> 비전 항목 수정은 **반드시 동결 전에** 끝낸다. 동결은 항상 마지막 Edit 이다.

1. `CLAUDE.md` 의 yaml 블록을 `onboarded: true` / `onboarded_at: <현재 ISO 8601>` 로 바꾼다.
2. `git add CLAUDE.md .harness/FOCUS.md && git commit -m "vision: 비전 · 금지선 · 품질 기준 동결"`
3. `대표님, 동결했습니다.` 한 줄 후 6단계로.

---

## 6단계 — 첫 기능 제안

`next-proposals` 스킬을 불러 **사용자 · 전문가 · 만드는 사람** 세 시야의 첫 기능 후보 카드를 만든다.
카드를 보여드릴 때 직접 기획하셔도 된다고 덧붙인다:

```
직접 기획하시려면 /js-ralph:feature <기획> 으로 바로 시작하실 수 있습니다.
```

---

## 주의

- 이 skill 은 **1회성** 이다. `onboarded: true` 이후 다시 호출되면 "이미 동결된 비전이 있습니다" 만 말하고 끝낸다.
- 재인터뷰는 대표님이 에디터에서 `onboarded` 를 `false` 로 직접 바꾼 뒤 세션을 재시작한다 (에이전트는 동결된 CLAUDE.md 를 고칠 수 없다).
- 초점(`.harness/FOCUS.md`)은 동결 대상이 아니다. 대표님이 언제든 바꿀 수 있다.
- 별도 vision 파일은 만들지 않는다. 기능 사양은 기획마다 `.harness/features/<slug>/SPEC.md` 에 생긴다.
