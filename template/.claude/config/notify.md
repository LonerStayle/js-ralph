# notify 설정 (FR-9)

notify-sender 스킬이 이 파일을 읽어 발송 채널과 메시지 schema 를 결정한다.

---

## 채널 설정

```
telegram_chat_id: CHANGEME
default_channel: telegram
```

- `telegram_chat_id`: onboarding 시 8번째 질문에서 수집.  
  값이 `CHANGEME` 이거나 비어 있으면 콘솔 fallback 동작.
- `default_channel`: 현재 `telegram` 고정. 향후 확장 예약.

---

## 메시지 schema

| 이벤트 | 상황 줄 | 기획 | 개발 | 다음 | 추가 필드 |
|--------|---------|------|------|------|-----------|
| `CYCLE_DONE` | `사이클 N 완료` | 이번 사이클에서 확정된 기획 항목 | 이번 사이클에서 완성된 기능 | 다음 사이클에서 할 것 | — |
| `STUCK_<phase>` | `<phase> 단계에서 막혔어요` | 막히기 전까지 확정된 기획 | 막히기 전까지 완성된 것 | 사람이 해야 할 것 | `막힌 이유: <비기술 한 줄>` |
| `PROJECT_DONE` | `프로젝트 완료` | 최종 확정된 기획 범위 | 완성된 기능 목록 (3~5개) | 운영·배포 다음 단계 | `최종 결과: <기능 목록>` |

### 작성 예시

**CYCLE_DONE (사이클 2)**
```
사이클 2 완료했습니다.

기획: 로그인 흐름 + 알림 설정 화면 확정
개발: 소셜 로그인(구글/카카오), 알림 on/off API 완성
다음: 사이클 3 — 결제 흐름 기획 시작
```

**STUCK_SPEC**
```
기획 단계에서 멈췄습니다.

기획: 결제 흐름 초안 작성됨 (미확정)
개발: 이번 사이클 구현 아직 시작 전
다음: 아래 사항 결정 후 알려주세요
막힌 이유: 무통장 입금 지원 여부를 결정해야 진행 가능합니다
```

**PROJECT_DONE**
```
프로젝트 목표 달성했습니다.

기획: 로그인·알림·결제·정산 전 범위 확정
개발: 총 4개 사이클, AC 전체 통과
다음: 실 서버 배포 후 사용자 테스트 진행
최종 결과: 소셜 로그인, 알림 설정, 결제 연동, 정산 대시보드, 관리자 화면
```

## 톤 가이드

- **수신자**: 대표님 (비개발자, 의사결정자)
- **언어**: 비기술 언어. 개발 용어(PR, gate-verify, merge, phase 등) 금지.
- **어투**: 경어, 일관된 격식체. 반말 혼용 금지.
- **길이**: 3~5줄 핵심만. 불필요한 수식어 제거.
- **숫자**: 사이클 번호, 완성된 기능 수 등 구체적 수치 반드시 포함.
- **구조**: 기획 / 개발 / 다음 방향을 명확히 분리. 독자가 스캔하기 쉽게.
- **STUCK**: 막힌 이유는 "결정이 필요한 것"으로 프레이밍. 에러 메시지 절대 노출 금지.

## inbox 저장 위치

수신된 답장은 `state/inbox/<ISO-timestamp>.md` 에 저장.  
ralph-tick 시작 시 inbox 를 확인해 사용자 지시가 있으면 우선 처리.
